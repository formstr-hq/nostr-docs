# E2E tests

A small, deliberately focused Playwright suite that exercises the core
nostr-docs flows end to end. These are **health checks**, not UI specs.

## Tests

- **doc-roundtrip** — sign in → create a document → write content → save
  (encrypt + publish) → read it back from the relay after a full reload. The
  core spine.
- **sidebar-list** — a saved document syncs back from the relay into the sidebar
  on load and reopens from there (the list read + open-from-list path).
- **backup-pages** — the account menu's Backup dialog exports a chosen set of
  pages as one zip of raw `.md` files, and the download is unzipped to prove each
  selected page landed with its own content.
- **import-pages** — the Import dialog reads single `.md` files and a `.zip` of
  `.md` files, creates a page per file, reports skipped non-Markdown inputs, and
  the imported content survives the encrypt → publish → reopen round trip. Also
  covers opting out of publishing to keep an import device-only.
- **relay-presence** — a page card's relay indicator names the relays holding the
  page, and when none do it shows a warning with a re-broadcast action (the test
  relay exposes a `POST /clear` control to empty it).
- **ai-writing** — verifies the Local AI writing settings, preference
  persistence, recommended GGUF links, Wllama model-loading options, correction
  normalization, serialized correction/autocomplete generation, and that an
  already-loaded session model survives disabling and re-enabling both tools.
- **sharing** — the v2 multi-writer spine: an open share link, a second identity
  editing it, live/offline convergence, and the privacy of the collaboration bus.
- **share-modal** — the Share dialog itself: generating a link keeps the dialog
  open and shows it, the editor is not remounted mid-flow, reopening shows the
  existing link, sharing an unsaved draft saves the page first, a view-only link
  opens for a fresh identity, repeated open/close is stable, and copy uses the
  clipboard.
- **sidebar-list** — a shared page opened via its link is classified as visited
  and only pages shared *by* you appear under the Shared tab.
- **draft-login** — an unsaved draft typed while logged out survives logging in
  (and a reload), and is cleared once the page is saved.

## Running

```bash
# from the repo root
npm run test:e2e            # headless
npm run test:e2e:ui         # Playwright UI mode
npm run test:e2e doc-roundtrip   # a single file
```

Playwright boots two servers itself (via the `webServer` config; both are reused
if already running):

1. a **local in-memory nostr relay** (`tests/e2e/relay-server.cjs`) on port 7449, and
2. the Vite dev server (`npm run dev` on port 5181), started with
   `VITE_DEFAULT_RELAYS=ws://localhost:7449` so the whole app reads/writes
   against the local relay only.

Browsers are installed once with `npx playwright install chromium`.

## Screenshots

Reference screenshots live under `Screenshots/`. They are regenerated by capture
specs that are skipped in a normal run:

```bash
CAPTURE_SCREENSHOTS=1 npx playwright test backup-import.screenshots
```

- `backup-import.screenshots` → `Screenshots/backup-import/` (backup dialog,
  import dialog, imported pages). Pins the `Corpo Docs` theme so the captures are
  byte-stable — a fresh profile otherwise picks a random theme.
- `release.screenshots` → `Screenshots/1.png … 3.png` (store images referenced by
  `zapstore.yaml`: editor light, editor dark, signer modal). Phone viewport.
- `relay-presence.screenshots` → `Screenshots/relay-presence/` (relay coverage
  popover, missing-everywhere warning).
- `local-relay.screenshots` → `Screenshots/local-relay/` (local-relay tag flow).
- `share-modal.screenshots` → `Screenshots/share-modal/` (view link, edit
  access, generated link, editors, copied) plus a short recording,
  `share-modal-flow.webm`.

## Notes on the realtime/MCP demo

`tests/e2e/realtime-mcp.spec.ts` is excluded from this suite (it boots a real
MCP server over stdio) and has its own config:

```bash
npx playwright test -c playwright.realtime.config.ts
```

## Principles

- Interactions are driven the way a **user** would: accessible roles, visible
  text, placeholders, labels — never CSS structure or test-only hooks.
- Each test uses Playwright's isolated browser context and creates an account
  through the real login modal; tests do not seed storage or signer internals.

## Notes

- No live relays — fast and deterministic, retries disabled so real flakiness
  surfaces. The relay is in-memory and wiped on restart.
- `DEFAULT_RELAYS` (`src/nostr/relayPool.ts`) honors the `VITE_DEFAULT_RELAYS`
  env var; it's unset in production. `doc-roundtrip` decodes the saved document's
  `naddr` and asserts the event is present on the **local** relay, so a broken
  override fails loudly instead of silently using live relays.
- The guest secret persists in `localStorage`, so a signed-in session (and the
  ability to decrypt its own documents) survives the reload the round-trip relies
  on.
